Step by step

In app.js, I enabled EJS rendering:
app.set('view engine', 'ejs');
app.set('views', path.join(__dirname, 'views'));
This tells Node/Express to render files from your views folder, including index.ejs.

I added a home route:
app.get('/', ...)
So when you open:

http://localhost:5000
Express renders your UI home page.

I added product routes like:
app.get('/:product', ...)
So pages like these work:

http://localhost:5000/akana
http://localhost:5000/perfecto
http://localhost:5000/blazemeter
Inside that route, Express reads the product from the URL:
const product = req.params.product;
For example, /akana means:

product = "akana"
Express checks filters from the URL query:
tag
days
start
end
So these URLs work:

/akana?tag=added
/akana?days=7
/akana?start=2026-04-01&end=2026-04-29
Based on the filter, your frontend app calls backend API using Axios:
const response = await axios.get(url);
Example:

http://localhost:3000/api/document/akana/getbytags/all
The backend API talks to MongoDB, gets the records, and sends them back to your frontend Node app.

Your frontend Node app sends those records into index.ejs:

res.render('index', {
  docs: response.data,
  product
});
In index.ejs, I added EJS rendering so the data appears on the page:
<% docs.forEach(doc => { %>
  <h4><%= doc.title %></h4>
  <p><%= doc.what_changed %></p>
<% }) %>
That means the UI is no longer only hardcoded HTML. It now renders live data from:

MongoDB Compass → backend API → Node/EJS frontend → browser
HTML has been converted into a Node.js rendered page. It still looks like your same UI, but now Express is serving it and EJS is filling in the data dynamically.



Product cards now route to Node pages like:

Filters are also clickable links:

Date range is a form:

And each document link is clickable if your backend record has link:

<a href="<%= doc.link %>" target="_blank" rel="noopener">Open document</a>
UI is not just static HTML anymore. It is now an EJS page rendered by Node.js, with clickable routes/forms/links that call the backend through app.js.

One thing to remember: if you add new buttons/filters in the HTML, they should usually become either:

<a href="/<%= product %>?tag=something">
or:

<form method="GET" action="/<%= product %>">
depending on whether it is a simple click filter or user input.

Added-
const baseURL = normalizeBaseURL(process.env.BASE_URL);

This line reads the BASE_URL environment variable from Node's process.env, passes that value into a normalization function named normalizeBaseURL, and stores the returned value in a constant called baseURL. The intent is to centralize and standardize the application's base URL (for building API endpoints, absolute links, etc.) so the rest of the code can rely on a consistent format.

Important runtime details: process.env values are strings or undefined (never other types), so BASE_URL can be undefined if not set. normalizeBaseURL therefore needs to handle undefined/null and return a safe, predictable string. The const binding prevents reassignment of baseURL later in the same scope, which is usually desirable for a configuration value.

Common normalization behaviors include ensuring a scheme (http/https), stripping or adding a trailing slash consistently, and removing duplicated slashes. Validation should also guard against malformed input (an accidental empty string, a relative path, or user-supplied values that could break URL construction).
